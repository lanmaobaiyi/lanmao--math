# 模块化数学建模运行规范

这是一套面向数学建模实际工作的知识库。它把原题阅读、条件核对、路线设计、数学建模、必要计算、数学验证、图表表达和答案交接组织成一条可追溯的工作链。它适用于数学建模竞赛、研究型问题、方案评价和需要清楚说明证据边界的分析任务。

## 这套规范解决什么问题

数学建模工作中，常见困难不是缺少算法名称，而是没有把题目要求、变量含义、数据条件、模型假设、计算结果和最终结论连成一条可检查的链。本知识库要求每个结论都能追溯到题面、数据、推导或实际核验，并且明确结论能够支持到什么范围。

规范同时处理四类容易混淆的工作。

- 把原题中的自然语言要求拆成全部必答子项，避免只回答大问题而漏掉比较、解释、证明或条件分析。
- 把事实、假设、情景设定、数学推导、计算结果和现实解释分开，避免把假设写成题面事实。
- 把可行性、最优性、收敛、稳健性、泛化、因果和现实有效性分开核验，避免用一个“运行成功”代替全部证据。
- 把每一问形成的对象、来源、单位、条件和限制交给下一问，避免上游变化后下游继续使用失效结果。

本仓库提供现行知识库、题型参考、记录模板和操作导航。具体题包、个人路径、聊天历史、运行环境和某一道题的结果应保存在对应的题目成果位置。

## 适合怎样使用

本规范可以用于完整赛题，也可以用于单独的证明、数据核对、模型推导、计算核验或图表整理。是否使用数据处理、代码、求解和图表，由当前问题的实际需要决定。

完整题包的推荐顺序如下。

1. 先阅读 数模运行基本规范/启动.md，确认阅读入口和文档分层。
2. 阅读 数模运行基本规范/知识库/通用/模块化总控与调用规范.md，确认任务范围、交接方式、返工位置、停止条件和完成标准。
3. 完整阅读题目和附件说明，先形成全题路线，标出各问之间的条件、对象、数据和结果依赖。
4. 按题号逐问实施。当前问形成直接答案、必要核验、适用图表和稳定交接对象后，再进入下一问。不同问题不并行开发或求解。
5. 根据当前问的缺口选择必要模块。模块可以合并，已经有效的成果可以引用，不要求每题机械创建八份报告。
6. 由 M08 逐项整理正式答案、成果索引、完成范围、限制和下游交接。未执行、不适用和待复核内容要保留真实状态。

如果只做纯解析或证明，可以重点使用 M01、M03、M04、A01 和 M08。如果题目包含数据和数值计算，再加入 M02、M05、M06，确有表达需要时使用 M07。

## 八大工作模块

八个模块是工作职责，不是固定软件，也不要求分别建立同名文件。每个模块都包含输入、实际工作、可交接输出和错误边界。

| 模块 | 主要工作 | 典型输入 | 主要交付 |
|---|---|---|---|
| M01 审题与需求 | 通读题目和附件，把每问拆成必答子项，保留原文定位，区分事实、要求、假设和可选增强 | 原题全文、公式、图表、附件说明、用户范围 | 需求清单、答案组成、关键歧义、问题关系 |
| M02 数据、观测与题给条件 | 核对题给条件和数据的来源、结构、单位、时间尺度、样本身份、缺失和合法性，说明数据能支持什么 | 原始资料、M01 清单、已有有效条件记录 | 条件核对、数据适用范围、缺口、处理依据和影响 |
| M03 分析与整体路线 | 从要回答的数学对象倒推方法路线，比较候选、基线、指标、预算、失败条件和证据安排 | 必答项、条件核对、资源边界、可用方法 | 全题路线、方法取舍、问题依赖、证据计划 |
| M04 数学建模与推导 | 定义集合、变量、参数、单位、关系、约束、假设、边界、目标或估计量，完成可检查推导 | 题意、路线、题给条件、数据语义、上下游需要 | 实例化模型、推导、参数来源、适用域、计算接口 |
| M05 本题计算实现 | 将已确认的公式和算法落实到本题代码或可复查计算步骤，核对输入输出、索引、单位、初值、边界和约束 | 已确认模型、题给参数、输出要求、核验计划 | 本题计算代码或步骤、依赖、输入输出说明、实现限制 |
| M06 求解、实验与数学验证 | 在授权和预算内完成主计算、必要核验、基线比较、收敛、复现、稳健性或适用实验，保留失败和未做项 | 有效模型、实现、输入、比较口径、停止条件 | 数值结果、对照、误差或区间、核验依据、失败与缺口 |
| M07 解释与图表 | 解释有效结果，按分析目的生成图组和图注，核对来源、单位、区间含义、标签、遮挡和提交尺寸可读性 | 当前有效结果、题目要求、证据限制、图表计划 | 图表、图注、可支持结论、不可支持范围和视觉核对 |
| M08 逐项答案与成果整理 | 逐个回答已选必答子项，整理正文、代码、图片、结果、来源、复现说明和交接状态 | 需求清单、各模块成果、跨问关系、交付范围 | 正式答案、成果索引、完成范围、限制、剩余缺口和下一步 |

M01 负责明确要回答什么。M02 负责确认用什么条件和数据回答。M03 负责安排怎样回答以及需要什么证据。M04 负责把题意变成数学对象。M05 负责把模型落实为本题计算。M06 负责获得结果并判断证据强度。M07 负责让结果可解释、可读和可提交。M08 负责把每个必答项整理成可以交接的答案。

## 两个横向职责

A01 和 A02 贯穿八个模块，但不替代模块本身。

| 职责 | 作用 |
|---|---|
| A01 重复复核与交叉审阅 | 从原题追到答案，再从结论反查前提、推导、实现、证据、跨问接口和图文一致性。不同文件或不同角色不自动构成独立证据。 |
| A02 组织与交接 | 根据当前缺口选择下一必要工作，完成一个可交接单元后继续、定向返工或请求必要决定，保持总目标和当前问题边界清楚。 |

## 一问一问的标准运行方式

完整题目先联合分析，实际求解再按问题顺序推进。

- 全题分析阶段由 M01 和 M03 查看所有问题及附件，梳理共同条件、问题关系、可复用方法、数值依赖和图表用途。
- 当前问阶段以“问题、必答子项、本次目标”为工作单元。只做当前问实际需要的模块，不顺带开发后问。
- 交接前要有直接答案、必要数学核验、适用代码或计算结果、所需图表和稳定的输入输出说明。
- 上游条件、模型或结果发生变化时，先标记受影响的下游结论为待复核，再沿真实依赖回查。未受影响且证据仍有效的部分可以复用。
- 逆向依赖、真实联立和必须带缺口续行时，说明最小联合范围、影响和需要的决定，不暗中跳问。

这种顺序可以减少前问修改后后问整体返工，也能让每一个问题的答案在进入下一问前保持可追溯。

## 按任务类型选择模块

| 任务 | 推荐路线 |
|---|---|
| 只做审题和路线 | M01，必要时 M02，随后 M03 |
| 纯解析、证明或关系推导 | M01 → M03 → M04 → A01 → M07 或 M08 |
| 有数据但不需要复杂计算 | M01 → M02 → M03 或 M04 → M07 → M08 |
| 优化、预测、评价或仿真 | M01 → M02 → M03 → M04 → M05 → M06 → M07 → M08 |
| 只检查已有结果 | 根据缺口选择 M02、M04、M06 或 M07，再由 A01 和 M08 交接 |
| 只整理最终答案 | 读取已有有效成果，由 M08 核对必答项、证据和成果位置 |

路线可以根据实际信息依赖裁剪。裁剪模块名称不等于裁剪责任，必要的题意、条件、推导、证据和交接仍要保留。

## 每个可交接成果应说明什么

无论交付的是公式、证明、方案、代码、数值、图片还是文字结论，都应说明以下内容。

- 它回答了哪个问题和哪个必答子项。
- 使用了哪些输入、来源、版本、单位和上游对象。
- 采用了哪些假设、适用条件、变量域和限制。
- 实际做了什么核验，哪些内容尚未执行或确实不适用。
- 哪些下游可以继续使用，哪些结论因变化而需要返工。
- 正式文件、代码、图片和结果位于哪里，接收者怎样读取。

状态至少区分已核对且满足标准、发现问题、未执行、不适用并附理由、待复核。文件存在、代码运行结束或单次结果较好，都不能自动升级为最优、稳定、泛化或现实有效。

## 模板和成果组织

需要记录时，按 数模运行基本规范/模板/README.md 选择对应模板。

- problem_contract.md 用于记录题目要求、范围和设计。
- 题面覆盖填写说明.md 用于检查原题到子项的覆盖。
- evidence_manifest.md 用于记录来源、版本和成果位置。
- claim_registry.md 用于关联关键结论与支持依据。
- verification_report.md 用于记录实际核验。
- robustness_report.md 用于记录适用的扰动和不确定性分析。
- 视觉验收说明.md 用于记录正式图表的实际打开和视觉检查。
- 共享、探针和 input 页面用于说明题目成果的组织、复现支撑和原始资料只读边界。

模板是记录格式，不是必须全部创建的文件。纯解析任务不需要空的代码目录，没有图表需求时不创建空图表记录。

## 建议的任务表达方式

提出任务时，至少说明原题或资料位置、问题范围、允许操作、成果位置、运行或不运行、预算与停止条件以及本次交付。可以直接使用下面的自然语言结构。

> 请按模块化数学建模运行规范处理本题。
>
> 原题与附件：说明资料位置和版本。
>
> 范围与必答项：说明全部题目或当前问题及子项。
>
> 允许操作：说明只读、写入、代码、计算、核验和出图权限。
>
> 交付：说明需要的答案、模型、代码、结果、图片或记录。
>
> 限制：说明原件只读、预算、停止条件和不能进入的材料。

任务没有明确授权时，不从“优化”“全流程”或“继续”推断出运行、上传、安装或扩大范围。

## 维护和核验边界

本知识库中的通用规则、题型公式和图表方法都带有适用条件。使用前先核对题意，不把参考公式当作当前题目的默认答案。

题意、数据、假设、模型或上游结果变化后，按实际依赖识别失效范围。旧结果可以保留为恢复依据，但恢复文件不会自动恢复证据有效性。计算预算应区分主计算、必要核验和适用成果处理，并在停止时如实交接最佳已核验结果和差距。

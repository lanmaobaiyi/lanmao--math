# 方法比较与改进（通用层）

本文件保留 `改进阶梯.md` 路径以兼容已有链接，内容不再定义模型复杂度等级。方法是否适用由题目和证据决定；复杂、耗时或使用搜索都不代表更可靠。

完整运行规则见[运行主规范](模块化总控与调用规范.md)。本页仅说明建模阶段如何比较、检查和改进候选；题型验收以 [题型协议.md](题型协议.md) 为准，结果与证据规则见 [KNOWLEDGE_BASE.md](KNOWLEDGE_BASE.md)。

## 一、形成可比较的候选

候选数量由题意、数据与资源决定，不设机械下限；一个合理候选也可采用。说明假设、数据要求、优点、限制、计算成本与失效模式；不必完整实现明显不适用的方法。候选参考与实际对照分开，宣称改善时不能因候选少而省略公平比较；不需比较主张的精确求值或纯证明按适用独立判据核验。

“基线 → 标准方法 → 有证据的改进”是比较思路，不是必须全部执行的阶段。基线可以是简单规则、解析结果、常数预测、经验关系或标准算法。它需要回答本题的同一目标，不能为了衬托复杂模型而选择明显失效的方案。

| 决策 | 依据 | 应保留的记录 |
|---|---|---|
| 采用基线 | 已满足问题契约，且验证支持所需结论 | 指标、验证证据与适用限制 |
| 采用标准方法 | 能回答原题要求，前提适用且核验支持所需结论 | 采用理由、核验依据与适用限制；涉及原题比较要求或方法优越性主张时，附公平比较证据与成本 |
| 改进现有方法 | 已量化误差、偏差、约束冲突或失效场景 | 缺陷、改进假设、验证办法 |
| 组合多种方法 | 子任务确有不同数学结构或信息来源 | 依赖、接口、误差传播与分别验证 |
| 停止进一步尝试 | 目标已满足，或收益不足、预算耗尽 | 停止理由、剩余限制与未执行检查 |

不以“没有创新”为理由强制增加算法复杂度，也不把能运行视为足够的交付证据。

## 二、公平比较与改进

- **先定比较口径。** 使用同一任务、相同原始输入、合理的数据划分和适用指标；记录预算、软硬件及随机性差异。
- **先量化短板。** 明确在哪个指标、约束、样本组、时间段或场景表现不足，再选择有针对性的改动。
- **把改动变成可检验假设。** 说明预期改善、可能代价及失败判据；在适用时用消融或单因素比较区分不同改动的贡献。
- **保护验证数据。** 调参、模型选择和预处理不得使用最终测试信息。时序按时间、组内相关数据按组、独立样本按适当随机划分；验证口径由题型协议与使用场景确定。
- **如实记录不确定性。** 随机方法比较重复运行的分布、误差或区间，不只挑最好一次；一次改善不足以自动推出统计或实际意义。
- **允许保留简单方案。** 若复杂模型的收益未超过不确定性、解释成本或运行成本，保留已验证的简单模型并说明取舍。

题目有明确目标优先级时，搜索与接收按该优先级比较；首级尚未满足或尚未证最优，固定其当前值优化次级，只能报告该固定条件下的改进，不能称完整层级最优，也不能让次级收益抵消首级退步。必要时分别安排改善可行方案与收紧有效界，观察实际目标、界或关键证据的增量；运行更久、增加约束或更换算法名不等于进展。允许探索临时较差状态的方法，应将探索状态与最佳已核验方案分开，正式替换仍按结果与证据第5节；不把这一优化题经验强加给无层级目标的任务。

### 计算成本确为瓶颈时

先区分输入处理、模型组装、求解与后处理的实际成本，再选择适用的索引预计算、稀疏表达或重复量复用。等价改写须保留对象身份、约束和目标；删边、剪枝、聚合或近似若改变数学问题，回M04说明依据与影响，不能以“优化代码”绕过。实际提速与正确性分别按同口径比较；目标值相同但决策不同，仍须核依赖具体决策的下游。未执行只说明预期，足够简单或已满足要求的计算不增加性能测量。示例可见[JuMP对模型组装中重复筛选的分析](https://jump.dev/JuMP.jl/stable/tutorials/getting_started/sum_if/)，不是要求使用该库。

昂贵的重复求值可按需考虑降阶、代理或多保真近似：先明确近似与原模型的输入、输出、适用域和误差依据，确定哪些工作可由近似承担、何时返回原模型校核或修正。最终结论须满足原题所需精度和约束，可依适用误差界或必要的原模型检查建立依据；回查一个候选不证明搜索完整或全局最优。达不到所需证据时保留受限结论或回到原方法，不以加速改变题意。参考Peherstorfer等[SIAM Review多保真综述（2018），第1.3、2.3及5.3节](https://epubs.siam.org/doi/10.1137/16M1082469)；高保真模型仍是模型，不等于现实真值，不替代必需观测验证。

## 三、针对结果查找反例

下表用于定位可能的反例，不是每轮必须重做的清单。按[总控A01](模块化总控与调用规范.md)检查新结论、变更影响或新增疑点；已有检查未变且证据仍有效时引用原记录，保留交接和最终回查的不同责任。只检查适用项，不适用说明原因，未执行不能记为通过。

| 检查方向 | 需要回答的问题 |
|---|---|
| 语义与量纲 | 参数数量级、符号、单位和范围是否符合题意？结论是否超出数据覆盖范围？ |
| 边界与约束 | 对空输入、零值、等号、容量边界或极端合法值如何处理？有约束时是否逐条回代？ |
| 数据与泄漏 | 是否重复使用同一对象或未来信息？训练与验证的预处理边界是否正确？ |
| 假设与适用性 | 分布、独立性、线性、稳态等假设是否是当前方法真正需要的条件？不满足时影响哪个结论？ |
| 数值与计算 | 精度、尺度、收敛容差、步长、迭代停止或超时是否改变结果？ |
| 扰动与随机性 | 需要时改变参数、初值、种子或数据划分，结果变化是否在可接受范围内？ |
| 题型专属结论 | 优化的最优性、预测的泛化、评价的排序、统计的推断、仿真的精度是否有对应证据？ |
| 独立复核 | 是否重新读取原始输入并采用独立检查方法，避免复用主模型核心函数或中间结果？ |

检查发现问题后，先说明影响并下调、撤回或标记受影响结论待复核；在授权范围内修正模型或实现，按主规范第0.2、0.5节决定能否实施必要复验。当前禁算时只做允许的文字或推导审阅，数值复验保留未执行，不因修正完成而自动恢复结论。若暂时无法解决，记录限制与实际问题，不得以“结果看起来合理”替代证据。

这里不单独定义题型门槛。是否需要上下界、滚动回测、AHP 一致性、置信区间、预热期或步长收敛，都由 [题型协议.md](题型协议.md) 和具体模型的适用条件确定。

## 四、记录与停止

优先沿用本题已有合理组织；下列路径仅为可选示例，不是必须创建的目录。只读任务可以在本轮回复交接，纯解析或局部任务不凑空文件。权威成果位置明确即可，不按目录名称判定有效性。

| 内容 | 记录位置与用途 |
|---|---|
| 候选、实验、失效案例和排除理由 | 已有过程记录，例如 `探针/`，供追溯和复核 |
| 最终方法、假设、取舍与限制 | 本题已有模型说明，如 `model.md` |
| 正式数值或解析结论与核验记录 | 已有结果文档或目录，例如 `results/`，标明权威位置 |
| 跨问题依赖与综合结论 | 已有综合说明，必要时可用 `汇总_跨问题/`，引用各问题正式成果 |

过程文件可不属于默认交付，但支撑正式结论的核验、复现和稳健性记录须可追溯。正式数字来自真实计算或推导，不手工篡改以改善结论；不要求软件冻结过程。

开始搜索或调参前明确预算和停止条件，不为所有算法或实验设置相同重复次数；按[运行主规范](模块化总控与调用规范.md)第0.2、0.5节管理授权与停止，不把算法内部正常迭代误当机械重试。停止不等于验证通过，达成目标后不为凑轮数继续。

## 五、采用或否定改进

一次改进留下“缺口—改动假设—预定比较—实际证据—上下游影响—采用/保留/停止”的简短记录。影响本问或下游硬要求时，不能用综合分数抵消违约；真实权衡按预定优先级或交用户决定。反例复核与重复审查统一按[总控A01](模块化总控与调用规范.md)，不另建重复验收表。

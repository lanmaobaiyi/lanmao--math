# 数学推演（通用层）

本页说明如何把题面转成可推导、按需计算和可验证的数学问题，不预设问题数量、优化目标或模型复杂度。术语、状态词和数学书写口径见[统一约定](统一约定.md)。完整运行规则见[运行主规范](模块化总控与调用规范.md)；题型验证要求以 [题型协议.md](题型协议.md) 为准；结果与证据规则见 [KNOWLEDGE_BASE.md](KNOWLEDGE_BASE.md)。

## 一、形成数学问题的四项工作

1. **抽取信号与边界**：识别对象、观测、决策、单位、时空范围、资源边界及交付要求。
2. **判定数学本质**：区分描述、解释、预测、评价、决策等任务，按子问题选择一种或多种题型。
3. **比较候选方法**：说明假设、数据要求、适用规模、解释能力、计算成本及已知失效模式。
4. **预先确定验证方案**：在看见主模型结果之前，确定适用的基线或独立判据、指标、数据划分、验证方法和停止条件；纯解析不制造训练划分或实验。

这些工作允许随新证据迭代，但不得跳过题意审查直接套用熟悉的模型。发生会改变模型或结论的歧义时，先明确问题契约再实现；一般实现选择由执行者根据已确定的契约执行。

## 二、从信号词识别对象

信号词只用于发现候选题型，不能代替上下文判断。区分题面事实、需要估计的参数和模型新增的假设。

| 题面信号 | 可能的数学含义 | 需要进一步明确 |
|---|---|---|
| 最优、最小、最大、在约束下 | 优化 | 目标方向、决策变量、可行域 |
| 预测、未来、趋势、随因素变化 | 预测或回归 | 预测对象、时间跨度、泛化范围 |
| 评价、排序、打分、综合、权重 | 多准则评价 | 指标方向、权重依据、评价对象 |
| 随机、不确定、概率、波动、风险 | 概率模型、随机过程或仿真 | 随机来源、分布依据、风险口径 |
| 网络、路径、节点、连通、流量 | 图论与网络 | 节点、边、有向性、权重、边界 |
| 变化率、传播、演化、增长、衰减 | 机理模型或微分方程 | 状态、时间尺度、初边值、守恒关系 |
| 分配、匹配、覆盖、选址、排班 | 组合优化 | 资源复用、离散性、容量约束 |
| 分类、判别、识别、聚类 | 分类或无监督学习 | 标签来源、类别不平衡、相似性定义 |
| 排队、到达、服务、等待 | 随机过程或离散事件仿真 | 到达与服务机制、稳态条件 |
| 显著性、差异、相关性、检验 | 统计推断 | 抽样机制、总体、估计量或假设 |
| 至少、至多、不超过、恰好 | 边界条件 | 严格或非严格不等式、等号含义 |

对会改变模型的歧义词和边界，各写一个最小可断言例子。无法解释清楚的条件不得直接编码为约束或筛选规则。

### 把要求落实为关系与推导

下面是M03/M04形成模型时按需采用的工作方法，不是另加一轮表单；内容落在已有问题约定或模型说明中，不要求保存内部思考过程。

1. **先写待答对象。** 用一句话明确要求确定什么，以及在哪些对象、时间和条件下成立。区分决策变量、待估参数、状态量与已经给定的输入；不要把一个尚待估计的量直接当题给常数。
2. **找生成该对象的关系。** 从定义、题给条件、守恒/平衡、几何/逻辑关系或明确的统计假设建立联系；每个关键关系指出来源。经验拟合、近似和情景设定分别标明，不能因工具需要而补入未经确认的实质假设。
3. **逐项翻译并反译。** 写清索引、变量域、单位和适用范围，把要求写为方程、不等式、概率条件、目标或待证命题；再用自然语言读回，检查是否改变了量词、等号、方向或对象。关键方向（如投影与厚度方向）、分母所对应的总体或基准，以及端点/边界含义也须与所求对象相容，不能仅凭量纲一致认定含义相同。目标与硬约束分开：不能仅靠一个惩罚项就宣称必然满足原硬约束；若采用软化或近似，交代等价条件或偏差并按流程确认。
4. **给出可复查推导。** 保留决定结论的等式、不等式、引理与依据；区分等价变换、单向蕴含和近似。除以可能为零的量、平方/开方、取对数、换极限或积分次序等操作都须核相应条件；新增或排除的解要回原式和定义域检查。求得驻点只提供候选，还须按目标比较边界、可行性及适用的极值条件。
5. **判断当前信息能确定什么。** 检查是否还有无来源的参数、未给的初边界或未闭合关系；仅数方程和未知量不能证明存在性、唯一性或可识别性。尝试从关系推导可确定的组合、构造不同对象给出相同观测的情形，或使用适用的秩、单调性等判据；判据自身前提也须说明。不能唯一确定不等于毫无成果：可交解集、范围或条件性关系，但不能冒充唯一点值。
6. **形成下游能使用的成果。** 给所求对象的表达式、解集或明确求解问题，附参数来源、适用域、近似及未解决项；若需计算，指出实际输入和应输出的数学对象，再交M05/M06。若纯解析已经足够，经相应审阅后交解释与答案，不为走模块补造实验。

两个符号情形用于说明判断方法，不是待执行题包，也不预设实际题目的模型：

- 若题目要求逐个核算需求的满足情况，允许缺额时定义非负分配量`x_ij`和非负缺额`u_i`，可写`Σ_j x_ij + u_i = d_i`；要求完全满足时应取`u_i=0`。单写`Σ_j x_ij ≤ d_i`只限制不超额，不能表达必须满足需求。单位和服务范围仍须由原题确定，不因示例含缺额变量就擅自放松实际要求。
- 若观测只通过`y=(a+b)x`依赖未知参数，且存在非零δ使`(a,b)`和`(a+δ,b−δ)`都满足全部条件，则这两组不同参数产生相同预测。即便数据能确定和`a+b`，也不能据此区分这两组参数；可传递该组合或说明补充条件的需要，不能任取一对称为唯一估计。若参数域或其他关系排除了这种歧义，则按那些条件重新判断，不一概宣称不可识别。

这些情形不替代实际题目的推导。对当前对象没有适用判据时如实保留未证部分，不凭经验给“模型成立”结论。

涉及从观测估计参数时，还要区分“模型在理想观测条件下可唯一识别”和“当前有限、有噪声的资料能否按所需精度区分”。依观测设计与误差假设，选择适用的区间、似然轮廓或敏感性/条件性分析；优化收敛、拟合相近或一个最优参数向量不能单独证明参数可靠。参数不精确也不自动否定所有预测，应分别核对所求组合、预测量或决策的证据及范围，给出必要补证而非任意固定参数；不涉及参数估计时不加此项工作。此区分参考Miao等的[SIAM Review综述第4节（2011，作者原文）](https://pmc.ncbi.nlm.nih.gov/articles/PMC3140286/)；该文另有[2023勘误](https://epubs.siam.org/doi/10.1137/23M1568958)修正式(6.23)，这里不采用该例公式。

## 三、候选方法与常见陷阱

下表是建模速查，不是验证清单，也不是由低到高的强制路线。实际必做验证、结果状态和强结论门槛统一查 [题型协议.md](题型协议.md)。

| 数学本质 | 候选方法族示例 | 可选工具 | 建模时需要检查 |
|---|---|---|---|
| 线性、整数与约束优化 | LP、MILP、CP-SAT | `scipy.optimize`、`pulp`、`ortools` | 目标方向、约束方向、整数性、可行性；宣称最优时检查证据 |
| 非线性优化 | 梯度法、SQP、多起点、全局搜索 | `scipy.optimize` | 尺度、初值、凸性；局部最优不等于全局最优 |
| 组合优化 | 动态规划、分支定界、启发式、元启发式 | `ortools`、`networkx` | 解空间规模、可行修复；最好一次不能称为全局最优 |
| 综合评价 | AHP、熵权、TOPSIS、模糊综合评价 | `numpy`、`scipy` | 指标方向、零方差、归一化、相关指标重复计权、权重依据 |
| 预测与回归 | 常数或经验基线、线性模型、树模型 | `statsmodels`、`sklearn` | 区分描述、推断与预测；涉及泛化评估时按使用场景划分并在训练部分拟合预处理；说明外推风险 |
| 时间序列 | 季节朴素预测、ARIMA、状态空间模型 | `statsmodels` | 未来信息泄漏、季节项、残差自相关；平稳性要求取决于模型 |
| 随机与不确定决策 | 场景法、鲁棒优化、机会约束 | `cvxpy`、`numpy` | 分布或不确定集合来源、概率口径、最坏场景可达性 |
| 图论与网络 | 最短路、最大流、匹配、图结构分析 | `networkx` | 图定义、边权符号、连通性；按任务检查容量、流守恒或路径合法性 |
| 机理与微分方程 | 解析解、数值积分、参数辨识 | `scipy.integrate` | 单位、初边值、可辨识性、刚性、数值收敛；守恒检查以实际方程为准 |
| 随机仿真 | 蒙特卡洛、离散事件、个体仿真 | `numpy`、`simpy` | 随机源、重复次数、估计精度、收敛性；稳态仿真才讨论适当预热 |
| 统计推断 | 参数检验、非参数方法、重抽样、贝叶斯方法 | `scipy.stats`、`statsmodels` | 抽样、独立性、效应量、置信区间、多重比较；相关不等于因果 |
| 分类与聚类 | 逻辑回归、树模型、距离或密度聚类 | `sklearn` | 分类关注泛化与类别不平衡；聚类关注距离、稳定性、有效性及实际含义 |

几项容易被误用的条件：

- **需要泛化评估时，划分不一律按时间。** 独立同分布样本可用随机划分或交叉验证；同一对象重复观测按组划分；未来预测按时间顺序划分，按需要滚动回测。特征构造、参数调优和预处理遵守相同边界。仅描述与总体推断按[题型协议](题型协议.md)选择证据，不因使用回归就强造训练/测试集。
- **AHP 一致性仅在使用判断矩阵时适用。** 记录矩阵阶数、计算方法、随机一致性指标来源及接受阈值；`CR < 0.1` 是常见约定，不是所有评价方法的通用门槛。
- **残差非正态不自动说明模型无效。** 判断具体估计、区间或检验是否依赖正态假设，并检查异方差、自相关、异常点和泛化表现；必要时采用稳健推断或重抽样。
- **固定种子不等于稳定。** 固定种子帮助复现一次运行，随机模型的可靠性还需重复试验、误差或区间及适当收敛检查。
- **多题型可以组合。** 一个子问题可先估计参数再优化决策，分别登记假设、验证和依赖；不能仅凭“含图”或“含随机数”跳过其真正任务的验收。

## 四、选择方法与资源预算

### 候选比较

候选取舍按[方法比较与改进](改进阶梯.md)执行，不机械规定数量。写清适用性、选择和排除依据；不完整实现明显不适用的方法，也不为凑数引入无关方案。需要比较主张时，候选名单不能替代实际对照证据；独立真值已足以核验的精确问题不强跑比较算法。

采用“基线 → 适用的标准方法 → 有证据的改进”的思路，但不设复杂度等级、不要求逐级实现。基线可以是解析解、简单规则、常数预测、已有物理关系或标准算法，必须与目标和指标对应。简单方法已满足契约时可以结束；方法的采用说明理由、适用性和核验依据，不因复杂就额外强制比较。原题要求比较或主张方法优于其他方案时，按同一任务、可比数据与指标及明确的预算条件提供比较证据；缺证据不作优越性主张。比较与停止方法见 [改进阶梯.md](改进阶梯.md)。

### 工具和计算

先明确数学方法，实际需要计算时再核所需工具和依赖。上表工具名只是可能选择，不是安装清单或对本机可用性的声明。优化按规模和结构考虑精确算法、求解器或启发式，其他题型按各自需要选择。纯推导不以环境检查为前置，不调用隔离实现。

按实际计算说明精度、搜索或调参范围及随机重复安排，不涉及的项目不补造。主计算、必要核验及适用成果处理的预算安排、确认、重估与停止统一按[主规范第0.5节](模块化总控与调用规范.md#05-预算停止中断与跨聊天恢复)，本页不另定预算规则；普通已授权工具使用不另加审批。

### 外部资料检索

- 从当前缺口出发，先核原题、活动成果和已有有效来源。方法前提、参数来源或外部事实会影响路线时，在审题或分析阶段尽早定向核实，不等实现后才寻找背书；资料完备且没有外部核实需要时，不为形式强制联网。
- 优先读原始文献、发布机构资料或官方文档。搜索摘要、转载与自动总结可作线索，不代替关键原文；核对所用定义、公式条件、版本、相关勘误或更正、时空范围、单位及其对本题的适用性。期刊声誉、引用量或GitHub热度不代替适用性与推导核对；已有答案不能替代本题的数据与验证。
- 用户要求查新，或依据涉及可能变化的标准、数据发布、工具接口等时，核实当前适用版本；发布日期、更新日期与本次访问日期分开，不因“较新”就替代题目指定的历史口径。实现参考与实际安装版本对应，不因文档更新自动升级依赖。
- 普通定向查证沿用现有授权，不另要求用户批准每次检索；耗时的多轮搜集、付费或新增资源按主规范第0.5节处理。先说清待解决问题，有足够适用依据就停止；关键依据仍缺失时保留缺口，不用重复检索次数代替证据。
- 对实际采用的关键来源记录机构/作者、题名或页面、链接/本地位置、版本或日期、具体段落/公式及用途，关联相应假设、参数、模型或结论；需复现检索过程时补充关键检索词，复用已有索引，不记录无关浏览流水。
- 原文无法取得、来源相互冲突或适用性存疑时，区分已核实与待核部分，说明对答案的影响；不伪造引文、不擅自平均或挑选支持预期结果的参数。经验或情景设定明确标为假设，并在需要时检查其影响。检索不授权上传私有原题或附件。

## 五、预先定义验证

验证项目从 [题型协议.md](题型协议.md) 选取并写入问题契约。明确原始输入、正式输出、检查方法、容差或统计标准，以及哪些情形不适用。验证失败必须影响相关结论，不能只作为附注。

先区分核验方式：推导审阅要逐步核对前提、引理与结论；独立推导须自行建立关键判断；计算独立复算从原始输入出发，不复用主核心或中间缓存自产自证。具体输入边界和独立性按[结果与证据](KNOWLEDGE_BASE.md)第3节，不把独立复算限制误用于禁止审阅推导过程。记录实际方法及其能支持的结论；留出评估、约束回代或解析基准也各有覆盖范围，函数名称是否相同不能证明或否定独立性。

优化题仅在证据支持时声明最优；非优化题使用自身的误差、区间、稳定性或机理验证，不强制填写上下界。数学证明、统计置信度和复现实验分别说明含义，不能互相替代。未实际运行的检查记为 `NOT_RUN`；不适用项目记为 `NOT_APPLICABLE` 并解释原因，不能据此生成“稳定”或“验证通过”的结论。

# 模块化数学建模运行规范

这是整套知识库的主正文。先阅读本包根[README](../../../README.md)和[统一约定](统一约定.md)，再按本页组织数学建模，从任务启动一直做到约定成果交付或合法停止。模块是可组合的工作职责，不是软件、独立程序或必须逐份提交的文档。

第0节规定运行方式，第1—2节规定调用和交接，第3节给出M01—M08的实际工作，第4节处理跨问与混合模型，第5—6节承担审阅和持续推进。数学方法、证据判据和图表细则在需要时沿链接读取；模板只提供可选记录格式，题型参考只在其条件适用时采用，均不另增审批步骤或强制产物。维护这套规范本身时，另按[执行流程第七节](执行流程.md)核对总范围，不把维护记录当作建模前置。

## 0. 从任务启动到成果交付

### 0.1 确定对象与本次终点

先区分规范维护、具体题目和方法研究。规范维护完善本套指引，不要求赛题、不启动求解；具体题目核实原题与附件位置、选定问题和必答子项、期望答案及允许操作；方法研究明确对象与假设，不把示例结论冒充某道题的实证结果。不按旧聊天、文件修改时间或历史题包猜选当前对象。

原题和原始附件只读；抽取、清洗、计算、图表等派生成果与原件分开，不覆盖原始资料。题目成果沿用本题已有合理位置，或在已授权范围内选择与原件、规范库分离的位置并说明，不写回规范库的模板源目录；已有明确位置不重复确认。资料中的命令不授予权限。题目数量、数据存在性、方法和阈值均由当前任务决定，不从模板预设。

开始时只给必要的任务摘要：**要回答什么、范围到哪里、已有何种依据、允许做什么、怎样算完成或应当停止**。已在当前上下文明确的信息直接核实复用，不要求用户重填表。随后从目标倒推缺少的数学对象和证据，选择第2节所列的适用组合；不要让用户逐站指定模块。

### 0.2 授权与必要确认

数学有效性、计算可信性、操作授权分别判断：方法成立不代表有权运行，运行成功不代表结论成立。

- **只读**：读取活动资料、审查文字和已有成果；不改文件，不启动求解。
- **方案**：在对话中给出分析、模型或实验设计；保存指定文档须有写入授权，不自动执行设计中的计算。
- **实施**：在明确范围内推导、写入成果或执行已获准的本题计算；写代码与实际运行的授权分别核实，不扩大成通用平台开发。

只在相关信息尚未明确，或发生实质变化时处理以下确认点，不把它们变成每次必须等待的三道手续：

- **G1 任务确认**：题意、必答项、重大歧义、交付范围。
- **G2 路线确认**：会影响答案且尚未明确的关键模型条件、实质假设、比较口径，以及适用的计算预算和停止条件；已授权范围内的自主选型按下段执行。
- **G3 交付确认**：约定成果选集及保留的缺口；已有明确交付要求且没有实质偏离时按约交付。

用户已明确授权在原题要求、既定条件、证据标准和资源范围内自主选择模型或算法时，执行者自行选择并说明依据，不因尚未指定模型或算法名称重复索取笼统路线批准。自主选型不包含改写题给事实、取消硬约束、偷换估计对象、把实证要求改成情景研究或擅自增加资源；模型不变时更换等价求解方法，不等于获准改变可行域。

尚未明确且会改变答案的实质假设，先说明不同选择、影响及所需决定，只询问该决定；此前继续独立且已授权的工作，或作不预断该决定的条件性推导，不执行依赖该决定的受限动作。

当前有效确认可以复用，普通模块切换、范围内可逆修正和不改变实质的实现选择不反复审批。题意解释、关键假设、目标/指标、资源追加或交付范围实质改变时，只重新确认受影响部分。用户新限制立即约束后续动作；受影响的旧决定不再授权后续动作，旧预算、旧确认或“继续”不能恢复当前禁止操作。

规范维护只修改获准的活动文档，不运行测试、题包或动态诊断。未来具体建模中的必要计算与数学核验须有当时授权，不构成恢复隔离软件的理由。隔离区禁用始终按根入口执行。

用户明确要求“先优化规范并审查，再执行题目”时，后阶段即使已有授权，也不能提前启动。先按[执行流程第七节](执行流程.md)完成约定的规范范围及写后审查，交接当前依据和未验证边界，再核后阶段的对象、授权与启动条件；局部条款改好或子任务已准备好代码不代表前阶段完成。用户要求先确认时等待该决定，否则不为已有充分授权另加审批；本轮明确禁算时不进入后阶段。

### 0.3 全题分析、逐问实施与交接

**先共同分析，再逐问实施。** 对完整题包，先联合阅读全部问题与附件说明，由M01/M03梳理共同条件、目标差异、数值依赖、方法复用及可能的联立关系，形成全题路线和各问所需证据、图表用途；不预设问数，不在整体分析时提前开发或求解后问。只选部分问题时，也核其实际依赖及必要的原题上下文，但不扩大求解范围。

实施默认按已选问题的题号顺序，一问达到下述交接条件后再进入下一问；无编号时先明确子任务顺序。不同时开发、求解多问，不以并行支线、后台任务、预计算或共享脚本名义让后问抢跑。本问内部仍按真实数学依赖选择模块、迭代和核验，不要求机械走完八站；本问确需的共享辅助可按需准备，不顺带实现后问。获准的本问内独立核验与协作不等于跨问并行，也不自动取得额外委派权限。

本规范中“继续独立工作”在具体建模时限定为当前问或已明确批准的例外范围，不隐含跳问许可。逆向依赖、真实联立及上游返工按第4节处理；规范维护不按题号推进，仍按执行流程第七节。

当前问以“问题＋必答子项＋本次目标”为工作单元，从尚缺答案倒推最近一个未满足条件：

1. **对齐要求**：M01把原题要求转成可回答的对象，并保留原文定位。当前已核实的要求直接沿用；未解决歧义只限制受影响部分。
2. **落实条件与路线**：核对所需条件及适用数据（M02或由M01/M04承接），M03安排真实依赖、方法取舍和证据计划。信息不够时明确缺口，不用方法名单代替分析。
3. **形成数学成果**：M04定义对象、关系、假设和适用域，按[数学推演](数学推演.md)形成可检查的推导、模型或条件性结论。纯解析结果在核对后直接进入解释与答案，不强行增加代码和实验。
4. **完成必要计算与核验**：需要且获准时，M05承接公式到计算的对应，M06求解并按[题型协议](题型协议.md)核验。实证结论检查观测依据，随机结论保留约定重复和失败，混合结论分别承担各路证据及连接处的检查；不能用一路成功代替其余证据。
5. **接收并回答**：作者自查后，接收方按第2节核对所需对象、来源、条件和证据。有效成果交M07解释，按需出图，M08按可交接子项形成或更新答案；状态标注与安全更新见M08，发现缺口按0.4定向返回。
6. **推进剩余范围**：A02先补齐当前问的必答子项及必要证据，再检查逐问交接条件；满足后接收该问并进入下一已选问题。一个模块、一轮审阅或一个子项完成不等于本问或全题完成；正常交接不要求用户逐模块说“继续”，用户另要求逐步确认时服从该约定。

**进入下一问的条件**：本问已选必答内容有直接答案；相应必要数学核验满足；适用代码、当前结果、所需图表与解释已形成并按相应规则检查；下游所需的具体对象、来源、条件和正式输入输出版本已选定，可稳定读取。沿第2节及M08的已有答案交接，不另建审批表或冻结系统。图号、交叉引用等全题编排可最后统一，不能借此延后本问必要分析或图片可读性检查。

满足约定的交付要求才称本问完成。若所需最优性证明、观测、核验或其他必答内容仍缺，先说明已有结果、具体缺口、对后问的影响和可行替代；只有用户明确接受该阶段性交接并同意继续，才可带缺口进入下一问，仍不得把原要求标成已完成。下游仅能使用其自身前提已满足、可核验的对象；用户同意续行不使无效结果变有效，也不把可行解升级为最优解。

必要职责可以合并，已有未变且有效的成果可以复用。不强制数据分析、写代码、出图、逐问双路重算或建立新台账；也不因省略模块名称而省掉条件、推导或核验。实际检查的状态和成果有效性按[结果与证据](KNOWLEDGE_BASE.md)区分，不用“已有文件”替代“可接收”。

### 0.4 缺口、失败与定向返工

先说明具体对象、触发条件、证据、影响和最小需要返回的成果，再交回对应职责：

| 缺口或失败属于哪里 | 返回位置及需要补回的内容 |
|---|---|
| 原题要求或重大歧义 | M01：原文依据、明确解释和受影响子项 |
| 来源、单位、样本身份或条件不支持用途 | M02或承接条件核对的M01/M04：有效来源、对应关系与适用限制 |
| 路线前提、比较或证据设计不成立 | M03：能回答原要求且可核验的路线及取舍依据 |
| 数学定义、关系、假设或推导错误 | M04：修正后的对象、模型/推导和变化影响 |
| 公式到计算的对应错误 | M05：修正的实现对应、输入输出及待重新核验项 |
| 求解精度、统计依据或结果核验不满足 | M06：失败定位、有效检查或明确的未解决结论；若原因在模型/实现，继续返回M04/M05 |
| 图文表达失真或整合遗漏 | M07/M08：与当前证据一致的解释、图表或逐项答案；源结果有误则返回其责任模块 |

修正后由作者复看原触发情形及相邻正常情形，接收方重核受影响接口，最终回查原题；未受影响且仍有效的证据直接引用。具体审阅责任和独立性按第5节，不因换角色名称假装增加独立审查者。

只停受缺口影响的部分，在第0.3节允许的当前问或已批准范围内继续独立工作。上游数值缺失时，可以推导不依赖该值的关系，依赖它的数值答案保持待定；必需实证资料缺失不能靠合成数据补成现实证据。局部任务不暗跑未授权上游，未选项保持可见，不为补依赖自行扩问。

真实耦合先按第4节说明联立或反馈的必要性，取得该例外范围的有效确认后实施，明确联合对象、初值、收敛及失败条件；不能因全题已授权就自行绕过逐问顺序，也不把数学耦合硬拆成不存在的单向关系。

缺工具时先尝试当前已获准且等价的现有工具、解析方法或有效成果；不得改变题意、精度和证据要求来宣称替代成功。不能等价承接则保留缺口，继续独立部分；不得自动安装、进入隔离区或降低核验标准。必须由用户决定时，只问具体缺失资料或决定，并给出影响和已尝试的安全替代，不把已明确的总方向再交回用户。

### 0.5 预算、停止、中断与跨聊天恢复

本题长计算、多轮搜索或新增资源之前，说明目标、适用资源上限、输出与停止条件，按第0.2节核实或取得必要确认；已有明确且有效的约定直接复用。普通工具按需使用；不自动安装依赖、下载权重、上传私有资料或启用收费服务。

对长计算，在当前约定预算内同时估计主计算、必要核验及适用的数据/图表处理、交付整理成本，分清约束的是计算资源、费用、总任务时长还是其他资源，不将一种额度当成另一种额度。安排主计算的分批观察点或限时控制，并为必要核验及成果处理安排可行资源，不能默认将全部额度交给主求解；估计须与本题规模相符，不设统一预留比例或重试次数。纯推导不为此虚构求解预算或增加环境检查。

声明硬停止上限时，同时明确实际控制办法，如求解器限时、逐批截止检查或本任务进程的超时控制，并在当前授权内落实；只在文档写“总计不超过某时长”不等于已有停止保障。工具不能保证该上限时说明限制，不把预计耗时写成保证；只终止归属明确的本任务动作，停止后的部分成果仍须按实际状态处理。

实际成本显著偏离估计时，在硬上限前按已有成果和剩余额度重估下一动作，优先停止已无必要收益的可选尝试；换用等价方法仍须保留题意、精度与证据标准。已知剩余资源不足以完成必要核验或交付要求时，提前说明受影响要求及可行替代；追加资源或改变范围按第0.2节具体确认，未确认不超额，也不把必要核验改成可选项。

达到约定目标、收益不足、预算耗尽、用户叫停、输入不可信或继续会污染结果时，停止相关动作并说明影响；不能用停止一项无增益计算代替完成其余总范围。没有新依据或不同策略的同因重试不继续，算法正常迭代和已约定随机重复另按原计划判断，失败与耗时不因换名称清零。

有本任务启动的计算时，中断后核实其实际进程归属；不按通用进程名批量终止，不知道是否退出就如实说明，不启动冲突写入。没有启动计算时记录未启动，不虚构进程检查。停止操作不等于已撤回其生成的结果，未核验成果保留实际状态。

交接沿用当前任务已有记录，记录日期/版本、总目标与授权、当前模块/子项、已完成及证据位置、剩余与未关闭项、有效/过期/未验证成果、变化影响、停止原因和下一合法动作；实际有计算才补充进程及累计/剩余预算。只读任务在回复交接，不为恢复另写文件；规范维护在当前对话简要交接，不自动新建或恢复历史台账。实际建模的必要来源、核验和交接记录仍随该题成果保留。

换聊天或恢复时重新核对入口、可用的当前任务记录/对话交接与相关实际文件，确认授权、来源/模型变化、有效成果、未完成范围和预算；恢复写入前核清目录归属、成果版本及部分完成状态，归属不明不覆盖。再从最近的有效交接点继续，不只继承最后一项小修订，也不因摘要写着完成就免查。具体题目对象或范围确实不明时才询问，不从旧题包猜选；规范维护不需要用户提供赛题。

**成果回退不同于进度接续。** 撤销错误改动前，先停受影响的写入，明确原因、精确对象及依赖范围，按[结果与证据第5节](KNOWLEDGE_BASE.md#5-结果变更与交付)核当前有效基准或待核起点，以及可靠恢复依据。在当前有效授权内，只撤销归属明确的必要改动，不整目录覆盖，不撤销无关成果；涉及他人成果须有针对该对象与操作的明确授权，归属不明仍不覆盖。恢复的内容可以只是待核工作稿；只有仍符合当前题意、条件和所需证据时，才能作为有效成果接收，不能回退题目要求来迎合旧答案。

恢复后核对受影响的模型、适用代码、结果、图表和答案是否配套，同步正式来源与引用，再按第0.4节及A01复看原触发情形、相邻正常情形和必要交接；不相关且有效的成果继续保留。不完整或不匹配的部分保持待核，恢复文件不等于重新计算或验证通过。无可靠可恢复内容、归属冲突或当前禁止读取所需材料时，不猜测还原、不重开旧资料或隔离材料，也不暗自重算；说明无法安全回退的部分及下一合法动作，继续独立且已授权的工作。

### 0.6 交付与完成判定

本次实际交付是**对约定要求的回答及其可信依据**，不是模块名称、文件数量或检查报告的集合。M08按必答项组织“直接答案＋必要条件＋关键推导/结果及核验依据＋限制”，附上适用的成果位置和复现说明；没有图或代码需求就不造图、不凑脚本，默认不写论文、不上传、不删除未知文件或依赖。

交付前按第5节做正反向回查：

- 正向：原题/任务要求 → 必要职责 → 数学对象与推导/计算 → 支持证据 → 对应答案。
- 反向：每项结论及图表 → 当前有效证据 → 模型、来源、单位、样本与条件 → 原始要求；跨问关系另核第4节的对象和误差传递。

本次全部必答项有与约定交付类型相符的成果、必要检查已完成、重要分歧已处理、图文与当前结果一致，才能说本次范围完成。涉及文件交付时，还须按M08核对实际目录、正式选集、阅读入口及必要依赖，不能只展示拟定目录树。只要求方案时，符合约定的方案可以完成该任务，但不等于求解完成；局部任务完成不能说全题完成。规范维护的整体完成仍以执行流程第七节为依据。

证明草稿、未运行代码、条件性答案及受限成果可以交接，但须明示状态；它们不能替代原本要求的已验证最终答案。缺观测、缺核验或缺约定独审时，说明受影响结论与补证需求，不以“不适用”抹掉必答项；有证据支持的不可行、不可识别或不成立结论则按原题要求如实回答，不为凑数值而编造结果。

最后简报已完成范围、真实检查、未做项和限制；仍有授权内必要工作就继续，全部约定范围完成就正常收尾。文档语义审阅不等于真实题目已验证，也不保证未来绝无错误。

## 1. 调用与分派

自然语言即可，例如：“只审查第二问的模型假设，先不改文件”“完善第三问与第二问的参数交接”“按已确认方案计算这一子项”。

需要结构化表达时可使用下面的文本，它不是终端命令：

```text
/数模 <动作> 对象=<规范整理|具体题目|方法研究>
资料=<已明确路径> 范围=<问题及子项> 模式=<只读|方案|实施>
任务=<目标> 限制=<不允许操作、预算和停止条件>
```

资料和范围可继承已核实的当前上下文；没有明确对象时询问，不按文件时间猜选。规范整理和方法研究不强制题包路径。模式与确认按第0.2节，不另立审批。

| 动作 | 职责 |
|---|---|
| 审题、数据、分析、建模、代码、实验、图表、交付 | 分别选择M01—M08 |
| 审查 | A01，默认只读；若另有明确文档修正授权，仅修正授权内容 |
| 优化 | A02组织相关模块；没有实施授权先给方案 |
| 全流程 | A02推进全部适用模块，不自动扩大已授权范围 |
| 状态、继续、停止 | A02核对当前事实、下一合法动作或停止收尾 |

新任务给简短摘要：本次目标、范围、允许改什么、所需前置、停止条件。普通模块切换不用重复确认，用户新限制立即覆盖旧计划。

## 2. 共同交接约定

工作单元是“问题＋必答子项＋本次目标”，不是固定问数或完整全题。只检查该单元实际依赖；未来图表和报告不是当前审题或推导的前置条件。

用已有需求记录、模型说明、计算结果或本轮回复完成以下交接，不另建平行台账：

1. **输入与前提**：原题定位、当前来源/版本、已确认条件、所需上游、未解决假设。
2. **成果**：本次回答了哪个子项，产生了什么对象、推导、代码、数值或结论，接收方是谁。
3. **证据与限制**：实际核验依据、未做项、不适用理由及适用域；不要只写“通过”。
4. **影响与下一步**：哪些下游可继续，哪些旧成果已不适用，返工责任与最小修复目标。

下游核对自己需要的单位、样本身份、条件和对象含义，不只是复制上游结论。对未变、仍有效的检查引用原记录；必要复核不因“去重”而删除。

原题所有必答子项保持可见；仅选择一项工作不抹除其他项。不可分的数学耦合先解释最小联合范围，不暗中扩问或重算上游。

### 按实际成果选择模块组合

先看本次要交付什么、已有什么有效依据，再选模块；不是先要求用户逐一指定八个模块。下面是常用组合，不代替模块卡或授权条件：

| 本次需要 | 可采用的组合与必要承接 |
|---|---|
| 只审题或给路线 | M01及所需条件核对，按需M03；交付需求/方案，不继续求解或把方案当答案 |
| 纯解析结论 | M01、所需M03/M04承接必要条件，A01核对推导后交M07解释/M08；可合并M02，不强做M05/M06或生成图 |
| 数值求解 | 需求、条件、模型明确后选择M05/M06；已有适用计算方法或工具可复用，不以新写代码为必要步骤 |
| 只解释或出图 | 核实已有结果的来源、版本、适用性与证据，再做M07；缺口回责任模块，不能为出图暗自重算 |
| 混合证据或跨问 | 为各结论选择实际需要的模块，按第4节交接或联合处理；同一路成功不替代其他必要证据 |
| 局部核对或成果整合 | 只调用相关模块、A01或M08，保留未选项；若是总目标的一部分，完成后由A02继续其余已授权单元 |

裁剪的是不适用的工作或独立步骤，不是责任：审题来源、必要条件、推导正确性、相应证据和回答范围不能因省略模块名称而消失。合并职责引用已有成果的承接位置，不增设裁剪表。具体M02条件见其模块卡；实际任务按第0.3节继续剩余范围；整套规范维护按执行流程第七节。

## 3. 八个工作模块

### M01 审题与需求

- **输入**：原题全文、公式图表、全部附件说明、用户范围。
- **工作**：先通读本次题包的全部问题和附件说明，再提取各问与每个必答子项；区分题面事实、要求、假设、可选增强。关键公式和表格回看原件，不只信抽取文本；局部任务仅核必要上下文，不扩大实施范围。
- **输出**：带原文定位的需求清单、每项答案应包含什么、相关条件与歧义、问题关系。
- **复核与交接**：再从原题找清单外遗漏，从计划答案反查是否答非所问。无法解决的重大歧义报告具体影响；不相关部分可交M02/M03继续。
- **边界**：不编造原文、页码或要求，不把“一问”当作只有一个子项。

**怎样开展**：按原文的“求出、证明、比较、解释、建议”等要求，明确每项最终应交的是数值、函数/关系、证明、方案还是解释，再标出对象、范围和限制。例如原文同时要求“给出方案并分析条件改变的影响”，方案与影响分析均须有对应答案，不能只交方案；原题没要求的增强则不擅自升级为必答。若两种题意解释会产生不同对象或可行域，写清差别与受影响子项，按第0.2节处理歧义；不影响本次目标的表述问题不阻断独立工作。清单保存位置沿用[题面覆盖说明](../../模板/题面覆盖填写说明.md)，不另建副本。

### M02 数据、观测与题给条件

- **输入**：原始资料、M01需求与当前已知的信息依赖；已有条件核对记录按需引用，不要求完整模型或核对报告先行。
- **工作**：核对当前子项必需的题给条件；有数据时查来源、结构、单位、时空尺度、样本身份、可得时间、缺失/异常与合法性。仅在适用且需要时，与M03/M04协同定义清洗、对齐、特征、划分、统计分析和参数来源。
- **输出**：条件与适用数据能支持什么、实际核对依据、缺口及影响；有处理时说明处理依据及派生数据与原件对应。可合并到已有审题或模型记录，不要求独立M02报告。
- **复核与交接**：有数据时区分真实零与缺测、删行与置空；涉及训练/评估划分时，预处理拟合仅使用相应训练部分，不泄漏评估信息；仅描述给定对象时按声明的分析范围处理，不强造训练集。总体推断与泛化预测的证据区别按[题型协议](题型协议.md)。抽样预览不能冒称完成全数据体检。接收方核对自己所需的条件与适用性，不以是否有M02报告判断前置是否满足。
- **边界**：原件不改；不以仿真值冒充观测，不因暂未用某附件就认定无用。

**裁剪依据是实际信息依赖与核对状态，不是题目名称或有无附件。** 可以跳过不适用的数据处理和统计分析；没有独立数据工作时，也可以不单独执行M02或生成其报告。但建模必需的题给条件核对不能遗漏，可在M01或M04中完成；沿用现有记录注明承接位置或引用及剩余缺口，不新增裁剪台账。

| 实际情形 | 必须保留的核对与可裁剪部分 |
|---|---|
| 非统计分析题但有数据 | 仍查来源、单位、对应关系、缺失及合法性；不强做无关统计分析，是否单独执行M02取决于独立数据工作是否需要 |
| 无数据附件但有题给参数 | 查参数含义、范围、单位和关系；可并入M01/M04，不因无附件免查，也不强做统计分析 |
| 纯理论或证明题 | 查定义、假设、变量域和命题条件；可并入审题与推导，不制造数据报告 |
| 必需资料缺失 | 保留受影响子项、缺口及补证需求；不以跳过M02掩盖证据不足，只继续不依赖缺失资料的部分 |
| 条件核对已经完成且仍有效 | 引用原记录，不重复劳动；来源、条件或用途变化时按影响定向复核，暂不能确认有效的部分不直接复用 |

无附件但有题给关系，可以在条件满足及当前授权内推导或计算；获准情景研究需明确设定来源，不替代必需的现实证据。不可识别、质量不合格、尚未使用和确实缺资料分别描述；裁剪不改变计算授权与证据门槛。

**怎样把条件交给建模**：

1. 从当前待答对象反查真正需要的量或前提，为其找到题面/附件/有效上游位置，注明已知、待估或仅为设定；资料存在不等于已满足当前用途，可解析不等于语义已确认，语义明确也须符合当前用途；尚未使用不等于无用。
2. 有表格需合并时，以对象标识、时间与空间粒度核对应关系；先辨明一对一、一对多或重复记录，不靠行号硬拼。换单位、聚合或对齐前明确含义，避免同一对象重复计入或把缺测补成零。
3. 清洗、删补、筛选或变换须有题意/方法依据；记录规则、受影响范围和原件对应，并核对适用的样本数、总量或范围变化是否有解释。并非每种变换都保总量，不机械要求不变；预测预处理仍遵守训练边界。
4. 对冲突来源或不确定参数，说明差异如何影响模型；不能擅自平均、择优取值或补成确定事实。能给条件性关系则标出条件，必需信息无法确定的结论保留缺口，必要时请求决定。

无独立数据工作时只保留适用的条件核对，以上说明不构成强制清洗流程。下游收到的应是“该量是什么、来自哪里、可用于什么、仍缺什么”，而不只是处理后的文件。

### M03 分析与整体路线

- **输入**：必答项、所需条件核对及适用的数据初查、可用资源；核对依据可来自M01/M04或已有有效记录。
- **工作**：从数学任务选择路线，比较适用候选及排除理由；设计适用基线/独立判据、指标、划分、试验、预算和失败条件。
- **输出**：各问如何协作、每个子项需要哪类证据、方法取舍和可执行方案。
- **复核与交接**：路线能否回答原题，所需前提是否成立；只有一个合理候选也可采用，不强凑算法。
- **边界**：方法名单、文献出现同一公式或工具可用不等于本题已建模。具体比较方法见[改进阶梯](改进阶梯.md)。

**怎样形成路线**：先把全题要求联系起来，从各已选答案对象倒推所需中间对象，区分可由题给关系推导、必须由观测估计、需要计算求解和仍缺信息的部分；明确哪些量共享、哪些问扩展前问、哪些仅复用方法。再按第0.3节安排逐问实施；逆向依赖或联立不隐瞒，按第4节先请求具体例外。候选先核必要前提，再比较能否输出该对象、证据能否取得及资源能否承受，最后说明采用/排除理由与失败时的替代方向。即使只采用一个方法，也要说清它如何回答本题；后续发现前提不成立，返回相应条件或模型工作，不靠增加算法名单弥补。

在已有路线或问题约定中预定各问需要解释的结构、结果、比较及核验关系，并按[图表规范第1节](图表规范.md#1-何时画画什么)判断应形成哪些互补图或图组、所需数据和计算从何而来。这里规划用途，不预填结果、不设每问一图配额，也不为画图提前求解后问；进入本问后依据有效成果落实或说明调整理由。

### M04 数学建模与推导

- **输入**：原题要求、路线、题给条件、适用的数据语义及上下游需要；必要条件核对可在本模块完成，不要求独立M02报告先行。
- **工作**：定义对象、变量域、参数、单位、关系、约束/假设、初边界、目标或估计量；推导模型并检查闭合、可识别性与适用尺度。
- **输出**：实例化模型、推导步骤、参数分类与来源、适用域、验证办法和计算交接。事实、假设、推导、情景设定分别写清。
- **复核与交接**：量纲、等号边界、极限、适用守恒、反例；缺定义返回M01—M03，不能在代码里偷偷补假设。
- **边界**：非优化题不强设最小化目标；不可识别参数不编造点值；纯解析直接交A01和M07/M08，不强制代码。

具体按[数学推演](数学推演.md)第二节的“把要求落实为关系与推导”工作：关系说明来源，变形保留条件，检查所求对象是否能由当前模型确定。交给下游的不是孤立公式，而是可回到题意、足以继续推导或计算的模型及未解决部分。

### M05 本题计算实现

- **输入**：足够明确且已确认的模型、题给参数或适用的数据说明、输出与核验计划。
- **工作**：将关键公式或算法步骤对应到实际计算位置，处理单位、形状、索引、初值、边界、约束和近似。只写本题所需代码，不开发规范运行系统。
- **输出**：可复查的本题计算方法或脚本、必要依赖、输入输出说明；必要的独立复核方法或脚本。直接公式计算或已有适用工具足够时不新造代码，但须说明公式、输入、关键设置及结果依据；复用对象不得来自隔离区。
- **复核与交接**：小实例、解析真值、性质或极端合法值按当前授权核对；未执行检查如实保留。代码发现模型未定义时回M04。
- **边界**：每个正式结果有明确的生成入口，可共享辅助代码；不强制“一问一个固定文件”或某种程序分支。独立复核不能复用主核心自产自证。

**怎样承接计算**：先把所求量与模型表达对应，再明确原始输入如何变为计算输入、输出怎样对应题目所求对象。使用数组或表格时写清对象标识与索引对应；可逆的缩放、无量纲化或变量变换保留逆变换及约束对应。非一一变换、聚合或降维不假定存在唯一逆变换，应说明分支、丢失的信息和当前仍可回答的对象；若原题需要的信息已丢失，须回原始来源或模型，不从汇总量编造个体结果。用离散化、截断或迭代近似时说明近似对象、精度依据和停止条件。不能让默认设置替代未定义的数学条件。

在获准的计算范围内，先用有解析依据、可手工核对的情形或适用性质检查关键翻译，再开展所需规模的计算；这属于本题数学核验，不建设软件测试系统，也不强制每题造小样本。对当前实例还须按原定义核对输出，不能凭小例子正确替代正式结果验证。仅获准写代码而禁算时，可作公式对应的文字核对，所有实际运行项目保留未执行。

对会决定答案的目标、变量域、索引、约束方向与边界，核对**实际交给计算工具的对象**，而不只检查准备赋值的变量。按工具能力读取模型表达、矩阵行/边界或等效摘要，重点检查数组副本、原位修改、默认值和索引错位是否使预期变更未生效；无法回读时用有依据的等效检查并披露覆盖限制。关键改动后先核这一对应，再开展长计算。M06还须从返回方案按原定义重算约束与目标；模型传入正确、求解器正常结束和方案满足题意是三个不同判断。状态含义见[结果与证据第1节](KNOWLEDGE_BASE.md#1-结论执行与检查分开)，例如[Pyomo结果源码](https://github.com/Pyomo/pyomo/blob/main/pyomo/opt/results/solver.py)区分局部最优、全局最优与未找到解；参考接口不等于指定本题工具。

读取活动结果、选定方案或跨问输入时，按[结果与证据第2节](KNOWLEDGE_BASE.md#2-最小证据对应)取得一致的来源快照，避免将不同写入时刻的内容和身份绑定。发现半写入或不一致数据先处理来源，不以空值、旧值代替本次输入。

实现较复杂时，按本题需要区分输入处理、模型构造、求解与结果表达，显式传递输入、对象标识和关键设置，避免依赖上次运行的隐含状态；这些职责可在同一文件中完成，不要求四份脚本或新框架。读取和交接数值前，按[结果与证据第1节](KNOWLEDGE_BASE.md#1-结论执行与检查分开)辨明库的返回对象及覆盖范围。实际成本构成瓶颈时，再按[方法比较与改进](改进阶梯.md#计算成本确为瓶颈时)定位并改进，不以代码更短或算法更复杂认定更好。可参考[JuMP的本题输入与模型组织示例](https://jump.dev/JuMP.jl/stable/tutorials/getting_started/design_patterns_for_larger_models/)，不照搬其包结构、语言或测试系统。

### M06 求解、实验与数学验证

- **输入**：有效模型、适用的计算方法或实现、输入和上游，以及计算授权、比较与停止条件；不要求先创建新脚本。
- **工作**：按需要做基线、主计算、校准、复现、独立核验及稳健性分析；保留失败与所有约定的随机重复。校准和选择不能污染最终评估。
- **输出**：当前结果、计算依据、实际误差或区间、对照、失败和未做项。
- **复核与交接**：按[题型协议](题型协议.md)判断结论；数值收敛、现实有效性、随机稳定性不混用。必要核验失败时不能标“已验证”。
- **边界**：这不是给规范软件跑回归测试。当前禁止计算时不以验证为名执行；缺口保留，不改验收口径制造成功。

**怎样判定结果可交接**：按拟支持的结论选择检查，先确认实际输出对应当前输入、数学对象与定义域，再检查相应约束、计算准确性或统计证据，最后判断能支持多强的答案。具体方法及覆盖限制见[题型协议](题型协议.md)“把验证计划落到判别动作”；不是每题全做。发现不符先区分来源/模型/实现/数值/统计问题，按第0.4节定向返回；保留失败证据及受影响结论，不只调整设置直至出现“成功”。

### M07 解释与图表

- **输入**：当前有效数值或解析成果、问题要求及证据限制。
- **工作**：解释结果及条件，落实M03按分析目的安排的图组；有图时由可定位代码承接有效结果，核对来源、单位、区间含义，并按图表规范在拟提交尺寸实际打开当前图。无需图时直接交接解释与条件，不生成空图表记录。
- **输出**：图、来源与图注、可支持和不可支持的结论；解析示意注明不是测量数据。
- **复核与交接**：图与答案一致，标签、遮挡和刻度可读；正式图不得悄悄换数据或调参。
- **边界**：探索图可在分析阶段使用并标明探索性质，不能冒充正式结果。具体格式与来源规则只见[图表规范](图表规范.md)。

**怎样解释**：先用当前数值或解析关系直接回答本子项，再说明比较对象、单位、分母及成立条件。解释变化时区分“结果显示的差异”“由模型关系支持的机制”“尚待验证的可能原因”，不从图形趋势直接断言因果；量化差异须有适用的参照和依据。需要图时先确定它应展示哪一数学关系，再选图型；无图时仍给清楚的文字/公式解释。敏感性不足以支持建议时说明限制，不把模型内结论自动升级为现实推荐。

### M08 逐项答案与成果整理

- **输入**：需求清单、每项当前成果、跨问关系与交付范围。
- **工作**：直接回答每个已选必答项，附条件和证据；检查关联结论，整理必要文件与复现说明。
- **输出**：可读答案、成果索引、已完成范围、剩余缺口与限制。
- **复核与交接**：文件存在不等于答题；空结果先区分有效数学对象、未获得输出或检查失败，按[结果与证据](KNOWLEDGE_BASE.md)记录原因与结论，不能强编数学解释；答案的强度不能超过支撑证据。
- **边界**：局部与全题完成分开。整理选集不删除依赖，不默认论文或上传。完成条件按第0.6节。

**怎样形成可用答案**：按已选原题子项组织“直接回答＋必要条件＋关键推导/结果及核验位置＋限制”，可写成段落，不强制新增答案表。题目要方案时给可实施的变量含义与约束范围，要证明时交论证，要比较时给同口径依据，不能只提供文件列表或算法名。

沿第2节的“问题＋必答子项＋本次目标”，每形成可交接的数学或证据成果，就形成或更新相应答案，不等全题结束才整理，也不按工具调用次数、段落数或固定时间强制写稿。有文件写入授权时更新本题已有权威答案位置；首次无答案文件时按本模块选定合理入口，不另建同义结果。只读任务在回复中交接。

已有足够证据的子项按上述结构直接回答；尚未核验部分明确为工作稿或待核，不计入已验证正式选集。同一文档可含不同状态子项，但状态与依据须紧邻各项，不能用整份文件一个“通过”掩盖未完成部分。状态与数值权威位置按[结果与证据第1—2节](KNOWLEDGE_BASE.md)，必要原始数值引用权威来源，不手工维护另一套数字。

安全更新按[结果与证据第5节](KNOWLEDGE_BASE.md#5-结果变更与交付)：同条件下尝试新候选时，原有效答案保留，未经核验的候选不能替代它；输入、题意解释或模型条件实质变化时，先将受影响旧答案明确为待复核或不再适用，不能因新稿未完成而继续把旧稿当当前已验证答案。替换前保留必要恢复依据并核清归属，之后沿实际依赖核下游答案、图表和引用；未受影响且仍有效的内容保留，恢复旧文字不自动恢复证据有效性。

当前单元交接后由A02继续选择下一必要工作，不因已写出一段答案就结束总任务；最终仍按第0.6节及本模块逐项回查并整理正式选集。

题目要求可使用的决策或实施方案时，还要让接收者知道：实际需要什么输入及何时可得、输出决定什么动作及其单位/适用对象、哪些资源与条件必须满足、输入缺失或超出适用域时哪些结论须停用并返回哪里。依原题所需的成本、时效、精度等核对可用性，不另加无关指标。模型内可行、当前环境可复现与现实可实施分别说明依据；缺少现场条件或应用验证时交条件方案及补证需求，不把仿真成功称为已落地产品。纯证明或仅要求分析的任务不增加部署工作，也不据此开发通用软件。

精简、拆分或搬迁成果时，按[结果与证据第5节](KNOWLEDGE_BASE.md#5-结果变更与交付)核对正式答案的语义保留及迁移后的使用声明，不以底稿仍在代替当前答案完整。

关联答案不一致时，先对齐来源版本、单位/时间尺度、总体/分母、条件与目标，再判断是表达差异、模型差异还是结果冲突；不能取平均或选较好数字掩盖矛盾。确有不同假设时分别给条件性结论，实质冲突返回责任模块，受影响部分未解决前不称整体完成。展示时按精度依据舍入并保留权威值；交付的可执行决策若因取整或舍入发生变化，须重新核对其约束，不能只修图文让它看起来一致。

**成套文件怎样组织并验收**：只有本次需要保存文件时才落实目录；只读答复或方案讨论不因此建文件。用户明确的交付地点、层次及命名优先；未另行约定时，采用以下按问组织，不把全部问题的代码、图表和结果平铺成一个混合目录：

```text
交付根/
├─ 00_交付说明.md             # 当前答案入口、范围、必要复现说明和限制
├─ 问题1_简明主题/
│  ├─ README.md               # 本问直接答案、解释、依据与限制
│  ├─ 模型与推导.md           # 需要独立展开时保留，可合并进本问答案
│  ├─ code/                  # 本问必要代码及核验代码（适用时）
│  ├─ figures/               # 本问选定的当前图片（适用时）
│  └─ results/               # 本问正式结果表、必要计算与核验依据（适用时）
├─ 问题2_简明主题/            # 按实际已选问题继续，不预设四问
└─ 共享_说明与复现/           # 确有跨问公共代码、材料或说明时使用
```

1. **按题而非按历史轮次分组。** 沿用原题问题编号，局部交付不将第二问改成第一问；无编号时用当前已明确的子任务名称。已有等效阅读入口不再复制同义文档。没有代码或图就不建对应空目录，但已有成果必须归入相应类别；“不强制造代码/图”不能解释成不整理现有成果。已有合理组织可沿用的前提是符合当前用户的目录要求，不能以沿用旧目录拒绝明确的整改要求。
2. **选出当前正式成果。** 逐文件确认它回答哪个必答项，或支撑哪项必要推导、核验、复现；过期答案、旧图、试错日志、聊天交接、阶段汇报及无关探索不混入正式选集。不以修改时间或文件名含“最终”代替内容判断；确需披露的失败与限制写入当前结论的依据，不靠隐藏不利记录制造整洁。
3. **过程留存与正式交付分开。** 上述过程材料留在本题原有工作区；用户要求持续记录时，在当前明确的一个工作记录位置更新，不逐轮新建台账。仅当用户明确要求随包保留时，集中于一个标明“非交付”的过程区，并在交付说明中区分。筛选不等于删除或移动既有材料，未获授权不清理历史目录；必要模型、源数据说明、核验依据及复现依赖不能当历史杂物排除。
4. **每问入口与依赖可定位。** 本问代码在`code/`给出明确调用入口，所需上游与输入路径在说明中写清；共享实现保留一个权威位置，不强制每问只含一个脚本。按[结果与证据第4节](KNOWLEDGE_BASE.md#4-复现不等于稳健或真实)说明入口执行重新求解、方案核验、结果重绘中的哪些职责，不将固定方案重放称为从零求解。缺少或过期的上游明确提示缺口，不暗跑其他问。正式交付不能依赖未随交付保留且未约定可访问的工作缓存、旧题包脚本或过程日志；允许引用已约定只读原始输入，不要求复制全部原件。问题间实施顺序按第0.3节及第4节，图号按正式答案阅读顺序，二者不混为一项顺序。
5. **从落盘结果验收。** 实际查看交付根及各问目录，将原题必答项逐一对应到当前答案、必要模型、适用代码、图片和结果；核查正式与过程材料分离、引用及依赖路径、遗漏与混入文件，并从每问入口反查是否仍需读者回底稿拼答案。随后按结果与证据第5节核语义与迁移声明；实际运行仅在授权内进行，未运行不能报“新位置可运行”。目录合规、语义完整和数学验证分别报告，一项通过不替代其余两项。

## 4. 跨问题与混合模型

### 顺序例外与上游返工

整体分析发现后问提供前问必需未知量，或多问存在不能拆开的联立/反馈时，先给出原题或关系式依据、严格单向求解为何不可行、最小联合或先行范围及替代办法，再请求用户明确决定。取得有效确认前只做不预断该决定的分析，不提前跨问开发或计算，不用猜值伪造前问完成。已明确的例外范围可复用，不扩成其余问题并行；联合范围内分别保留各问要求和证据，完成后回到原逐问顺序。纯方法复用或实现方便不构成联立例外。

交接后上游需要实质修正时，先暂停使用受影响上游的下游实施，回到上游责任模块；按[结果与证据第5节](KNOWLEDGE_BASE.md#5-结果变更与交付)标明失效范围、保留恢复依据并重新核验。上游再次满足第0.3节交接条件后，依次重核受影响后问的输入、结果、证明、图表和答案。比较的是具体对象与条件，不只是数量或目标值；不同时改上游并发布依赖旧布局的下游正式成果。未受影响且有效的成果保留，不借返工重新并行开发其他问。

### 交接对象与关系

| 关系 | 交接时保留 | 反向检查 |
|---|---|---|
| 数据/结果传递 | 当前值、样本对应、单位、顺序、尺度及来源 | 下游是否实际使用、是否足够回答其任务 |
| 参数继承 | 来源、估计条件、范围、不确定性和相关性 | 是否仍适用，误差是否被当成确定值 |
| 模型扩展 | 保留/改变的假设、新变量与约束 | 是否回答新增要求，是否破坏前问结论 |
| 方法复用 | 方法及独立输入 | 不误标成数值依赖 |
| 联立或反馈 | 联合关系、初值、求解和收敛条件 | 不能硬拆为单向流程，也不能把迭代成功当证明 |
| 纯叙述顺序 | 顺序理由 | 不虚构数据交接 |

先从后问所需对象反查前问提供什么，再正向核对同一情景下的使用与误差传播。未来观测、后问标签不得泄漏到前问训练。共享样本或共同参数造成的相关性不能随意按独立处理。

新增约束可能不活跃，上游扰动后下游也可能不变；先看理论依据，不强求“必须产生差异”。解析结论传给计算时带上变量域与条件，计算结果支持证明时不能把有限算例升级为一般证明。

### 怎样传递不确定性

对真正依赖上游估计的下游结论，先指出下游关系中哪些位置使用了该量；接收点值之外，核实其误差界、区间、分布或情景的含义与来源。不同置信区间不能直接拼成同置信水平的联合区域，情景范围也不能当概率分布；缺少关系信息时不擅自假定独立。

按当前数学任务选适用的传递方式：能推导时用定义域内的界、单调性或有条件的近似；需计算时在授权内作保持相关结构的联合扰动或抽样，并说明覆盖范围。若只做局部近似，保留近似点及误差/局限；只传点值时把下游写为条件于该点值的结果，不宣称已经覆盖上游不确定性。是否改变最终阈值判断、可行性或排序须回到下游目标核对，不仅展示参数变化。

例如同一上游量a在下游以`z=a−a`出现，任何保持“同一个a”的联合变化都给出z=0；把两处a独立扰动会制造并不存在的差异。反之，两个不同来源的量也不能因数值相等就当成同一对象。该符号说明用于检查身份和依赖，不要求每题做随机模拟。

## 5. A01：重复复核与交叉审阅的唯一约定

### 5.1 审什么

每次审阅从批判性数学建模立场出发：不因作者写了“完成”就预设成立，也不为扮演批判者强凑缺陷。先问该步骤是否确为回答原题所需、定义与假设是否支持数学关系、证据是否足以支持实际主张、成果是否可理解和使用；已有充分依据时保留，不以增加流程代替解决问题。再按下表正向查遗漏与错误承接，反向查对象偷换、未证前提和过强结论；交付的是可检查依据与发现，不是内部思考过程。

审查范围从原始任务及用户明确的交付要求建立，再与作者清单和现行规则对照，不能只证明已写条款彼此一致。审查既有运行问题时，先核清是哪一道题、哪次运行及其完整问题记录，再回实际对象核验；多个题目或运行分别列清来源，不能以最近聊天的问题代替全部范围。问题是否关闭按[结果与证据第1节](KNOWLEDGE_BASE.md#1-结论执行与检查分开)判断，缺少对应材料时不作全体已解决声明。

| 层面 | 正向追踪 | 反向质疑 |
|---|---|---|
| 需求 | 原题→子项→答案 | 是否漏掉未登记的原题要求，是否答非所问 |
| 数学 | 对象→假设→推导→结论 | 前提、单位、边界、反例是否支持 |
| 计算（适用时） | 公式→实现→输出 | 初值、索引、约束和近似是否错译 |
| 证据 | 原始来源→核验→结论 | 是否同源重复计信、泄漏、挑选或旧结果 |
| 跨问 | 上游→接口→下游 | 对象、相关性、条件与误差是否丢失 |
| 交付 | 当前结果→图文→答案 | 图表是否误导、是否扩大范围或强度 |

按风险覆盖关键链，不默认每问完整双路重算。审阅也要核对检查方法本身：正确对照应被接受，已知错误应能被发现；不能只看作者写的“通过”。用正反例检查某个判别方法时，必须让这些对象经过该方法的实际判别步骤或入口并观察接受/拒绝及原因；只证明人为改过的数值确实不同，不证明正式核验方法检出了错误。当前只能作文字审阅时，说明判别逻辑与未执行范围，不补写动态检出结果。

### 5.2 哪些重复要保留，哪些不要

- **保留不同责任的复核**：作者完成模块后的自查、接收方对交接条件的核对、最终从原题回查答案。三者目的不同，可引用同一有效证据，不各建一份台账。
- **交叉核验要有不同依据**：独立推导、约束回代、解析真值、留出观测或不共享主核心的复算。多份报告、不同文件名、不同角色名不增加独立性。
- **变更后定向重查**：先列变更与影响，再查受影响假设、计算、图表及下游。内容未变、证据仍有效且无新疑点时，不重复全链审查。
- **缺陷修正后闭环**：复看原触发条件及相邻正常情形，核上下游影响。当前禁算时只做文字/推导核对，数值复验保留未做，不能说“已修改即已验证”。
- **停止无增量重审**：没有新证据、新变更或未决矛盾时不再要求“审查审查报告”；不靠轮数或连续“无问题”证明可靠。

### 5.3 独立性与发现记录

同一执行者多轮自审仍是自审。第二审查者须真实存在，并从原始资料重新建立关键判断；只读主作者摘要或共享错误前提不能称完整独立审阅。委派须有平台能力和用户授权，不以角色扮演代替。

缺独立审查时披露范围与影响，不宣称相应认证或已满足约定独审要求；不阻断不依赖该项的本地工作。

每个发现记录位置、触发条件与证据、影响、修正理由、所需复核和实际结果。疑点与已证实问题分开。数学分歧以原题、推导、观测和判别证据处理，不靠多数票。自查结论只能覆盖实际阅读和检查的范围。

## 6. A02：组织与交接

明确对象及授权 → 选择当前模块和必要材料 → 核前置 → 完成一个可交接单元 → 按A01做相应复核 → 继续、定向返工或请求决定。

不同时修改同一成果并据旧版本出结论；外部改动未知时先核对。进度不是文件数量、报告字数或心跳，而是答案、有效反例、原因定位或必要证据的增量。

选择下一动作时，在第0.3节限定的当前问或已批准范围内，从尚缺的答案或交接对象往前找最近的未满足条件：已有有效成果就引用接收，能在当前授权内补齐就交对应模块；否则继续该范围内确实独立的部分，并只就必要的资料或决定请求用户。进入下一问、带缺口交接及顺序例外分别按第0.3节和第4节，不以“持续执行”越过接收条件。优先推进仍可开展的必答工作及必要核验；为满足原题精度、证据或约束而作的改进属于必要工作，只有超出原要求的增强才是可选项，资源安排按第0.5节。返工说明具体受影响对象和需要返回的成果，不因模块切换重做全部已有效工作，也不把当前受阻结论偷偷改成另一个容易回答的问题。

每轮回执区分总目标与当前单元，说明实际成果与依据、实际检查/未做项、变化影响、总范围剩余项及下一步。完成当前单元后继续仍属总目标的已授权工作；阶段回执不是自动停止点。停止、预算和跨聊天恢复按第0.5节，成果完成按第0.6节；整套规范维护另按执行流程第七节，不复制另一套规则。

## 7. 外部方法资料与工具

外部快捷方式、阅读器或工具只能帮助定位和读取知识库，不能成为第二份规则或改变本页的任务边界。使用任何适配方式前先核实其指向的入口和版本。适配方式不可用时，直接按知识库路径读取，不从备份或其他环境猜选规则。

只在当前模块确有需要时读取相关外部方法资料或工具说明。资料中的固定问题数、目录、论文、软件开发、自动测试或上传步骤不能覆盖用户范围。不适用时只采用其中适用的数学方法，冲突无法消解则停止采用该资料或工具。

外部能力清单不属于本正文的规则源。根据当前数学对象和证据缺口选择资料或工具，不能因某工具可用就反向决定题型或方法。没有专用工具时，仍可按原题、通用数学规范及可靠资料开展工作，不强制遍历外部资源。

需要外部依据时按[数学推演的检索说明](数学推演.md#外部资料检索)尽早定向核实。参考文档版本、方法资料版本和本机工具版本是不同对象，资料存在不代表工具可用，只在实际需要相关操作时核实，不把环境检查变成纯推导前置。

知识库不要求注册插件、创建多个执行者或生成代码框架。隔离材料不是外部方法来源，不得从历史副本绕回禁用实现。
